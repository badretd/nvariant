# «N-вариант»: уточнённая техническая концепция

## 1. Модель публикации

Сайт работает по принципу **code-first publishing**.

Материалы создаются непосредственно в репозитории сайта. После коммита и деплоя новая статья или выпуск сразу становятся доступны.

Не нужны:

- отдельный сервер;
- база данных;
- административная панель;
- система пользователей;
- редакционные роли;
- планировщик публикаций;
- автоматическая история версий.

История изменений хранится в Git, но читателю показывается только вручную заполненный раздел правок.

# 2. Технологический стек

Рекомендуемый стек:

- Next.js;
- TypeScript;
- React;
- MDX для обычного текста;
- React-компоненты для интерактивных блоков;
- CSS Modules или Tailwind CSS;
- Motion для интерфейсных анимаций;
- SVG или Canvas 2D для процедурного фона;
- Vercel для сборки и размещения;
- GitHub как источник контента и история изменений.

Основная модель:

```text
Контент в репозитории
        ↓
Сборка Next.js
        ↓
Статические страницы
        ↓
Деплой
        ↓
Материал сразу доступен
```

Большая часть сайта должна генерироваться статически. Серверные запросы при чтении не требуются.

# 4. Материал

Материал является основной единицей контента.

Материал может:

- существовать самостоятельно;
- входить в один выпуск;
- сначала появиться отдельно, а затем войти в выпуск;
- сначала появиться в выпуске, а затем стать доступным в архиве материалов;
- никогда не входить в выпуск.

Один полный материал не может входить сразу в несколько выпусков.

Для повторного использования небольших фрагментов существует отдельная система цитат.

---

## 4.1. Файл материала

Обычный текст пишется в MDX:

```mdx
# Название материала

Вступительный абзац.

<InteractiveDiagram id="example-diagram" />

Продолжение материала.

<Media
  id="city-photo"
  src="/media/city-photo.webp"
  alt="Описание изображения"
  author="Имя автора"
  source="Название источника"
  license="CC BY 4.0"
/>
```

MDX позволяет одновременно использовать:

- обычный Markdown;
- React-компоненты;
- интерактивные схемы;
- анимации;
- галереи;
- видео;
- нестандартную типографику;
- экспериментальные блоки.

Для особенно сложных материалов можно создавать полноценный `page.tsx` или отдельный React-компонент, но базовым форматом остаётся MDX.

---

## 4.2. Метаданные материала

Каждый материал получает отдельный файл метаданных.

```ts
export const metadata = {
  slug: "example-material",
  title: "Название материала",
  description: "Короткое описание материала",
  publishedAt: "2026-08-01",
  readingTime: 8,

  authors: ["author-id"],
  tags: ["культура", "технологии", "эссе"],

  issue: "issue-001",

  showInMaterialsArchive: true,

  cover: {
    id: "example-cover",
    src: "/media/example-cover.webp",
    alt: "Описание обложки",
    author: "Имя автора",
    source: "Источник",
    license: "CC BY 4.0",
  },

  corrections: [
    {
      date: "2026-08-05",
      text: "Исправлена фактическая ошибка в третьем разделе.",
    },
  ],
};
```

Тип материала не задаётся отдельным полем. Вместо этого используются теги:

```text
интервью
эссе
заметка
фотография
видео
исследование
человек
музыка
технологии
```

Так одна публикация может одновременно считаться, например, интервью, материалом о музыке и частью раздела «Люди».

---

# 5. Авторы

В конце каждого материала располагается блок авторов.

Он содержит:

- имя;
- роль в материале;
- короткое описание;
- фотографию или аватар;
- ссылку на страницу человека;
- ссылки на другие материалы с его участием.

Пример:

```text
Авторы

Иван Иванов
Автор текста

Анна Петрова
Фотограф
```

Один материал может иметь несколько участников:

- автор текста;
- редактор;
- фотограф;
- иллюстратор;
- герой интервью;
- оператор;
- композитор.

Однако на первой версии необязательно показывать все внутренние редакционные роли. Можно отображать только публично значимых участников.

# 6. Раздел «Люди»

На сайте появляется отдельный раздел:

```text
/people
```

Он содержит всех людей, связанных с материалами журнала.

Для каждого человека показываются:

- имя;
- фотография;
- короткое описание;
- роль или область деятельности;
- количество связанных материалов;
- раскрывающийся список материалов.

Интерфейс:

```text
[ Поиск по людям и материалам ]

Имя человека                         4 материала
Короткое описание                    [Развернуть]

    Название материала
    Выпуск №1
    Дата

    Название другого материала
    Отдельная публикация
    Дата
```

Поиск должен работать одновременно по:

- имени;
- псевдониму;
- описанию;
- названиям связанных материалов;
- тегам материалов.

Фильтрация выполняется на клиенте, поскольку объём данных в первой версии будет небольшим.

# 7. Цитаты

Цитата является отдельной сущностью и может использоваться в разных выпусках и материалах.

```ts
export const quotes = {
  "quote-example": {
    text: "Текст цитаты.",
    author: "Имя человека",
    source: "Название материала",
    sourceUrl: "/materials/example-material",
  },
};
```

Использование:

```mdx
<Quote id="quote-example" />
```

Цитата может ссылаться:

- на внутренний материал;
- на выпуск;
- на внешнее произведение;
- на интервью;
- на выступление;
- на первоисточник.

При использовании цитаты из внутреннего материала пользователь может перейти к оригинальному месту публикации.

# 8. Выпуск

Выпуск — отдельная конфигурация, определяющая порядок материалов.

```ts
export const issue = {
  number: 1,
  slug: "issue-001",
  title: "Название выпуска",
  description: "Описание выпуска",
  publishedAt: "2026-08-01",

  cover: {
    id: "issue-001-cover",
    src: "/media/issue-001-cover.webp",
    alt: "Обложка первого выпуска",
    author: "Имя автора",
    license: "CC BY 4.0",
  },

  sections: [
    {
      id: "introduction",
      title: "Вступление",
      blocks: [
        {
          type: "editorial",
          component: "IssueIntroduction",
        },
      ],
    },
    {
      id: "people",
      title: "Люди",
      blocks: [
        {
          type: "material",
          material: "first-material",
        },
        {
          type: "quote",
          quote: "quote-example",
        },
        {
          type: "material",
          material: "second-material",
        },
      ],
    },
  ],

  corrections: [
    {
      date: "2026-08-05",
      text: "Обновлена подпись к фотографии во втором разделе.",
    },
  ],
};
```

## 8.1. Ограничение принадлежности

Во время сборки должна запускаться автоматическая проверка:

- материал не включён в два разных выпуска;
- все указанные материалы существуют;
- все авторы существуют;
- все изображения имеют метаданные;
- все ссылки на цитаты корректны;
- идентификаторы разделов не повторяются;
- номера выпусков уникальны.

При нарушении правил сборка завершается ошибкой.

Это заменяет проверки, которые обычно выполняла бы база данных.

# 9. Страница выпуска

Выпуск отображается как одна большая страница.

Структура:

```text
Обложка выпуска
Название
Описание
Время чтения
Авторы и участники

Оглавление

Раздел 1
    Полный материал
    Цитата
    Редакционный переход

Раздел 2
    Полный материал
    Медиа
    Полный материал

Раздел правок
Информация о выпуске
```

Материалы вставляются полностью. Они не отображаются как карточки или сокращённые превью.

---

## 9.1. Боковое меню

На компьютере используется закреплённое боковое оглавление.

Оно строится из:

- разделов выпуска;
- названий материалов;
- основных заголовков внутри материалов.

Пример:

```text
01. Вступление

02. Люди
    Первый герой
    Второй герой

03. Идеи
    Название материала
    Другой материал

04. Заключение
```

Подсвечивается:

- текущий раздел;
- текущий материал;
- прогресс чтения.

---

## 9.2. Мобильная навигация

На телефоне боковое меню заменяется компактной кнопкой:

```text
Содержание · 37%
```

По нажатию открывается панель со всеми разделами и материалами.

Дополнительно внизу экрана отображается тонкий индикатор прогресса.

---

## 9.3. Пагинация

Основным режимом остаётся непрерывная большая страница.

При необходимости можно добавить альтернативный режим чтения по частям:

```text
/issues/issue-001/1
/issues/issue-001/2
/issues/issue-001/3
```

Однако это не должна быть классическая пагинация по произвольному количеству символов.

Выпуск делится только по редакционным разделам:

```text
Часть 1 — Вступление
Часть 2 — Люди
Часть 3 — Идеи
Часть 4 — Послесловие
```

На первой версии лучше оставить одну непрерывную страницу, но загружать тяжёлые интерактивные элементы только при приближении пользователя к ним.

---

# 10. Отдельная страница материала

Страница материала содержит тот же полный текст, что и выпуск.

Если материал входит в выпуск, сверху или снизу указывается:

```text
Материал входит в выпуск №1 «Название выпуска».
```

Доступны действия:

- открыть материал внутри выпуска;
- перейти к началу выпуска;
- посмотреть другие материалы автора;
- открыть связанные изображения;
- скачать доступные медиа.

Если материал не входит ни в один выпуск, он просто существует как самостоятельная публикация.

---

# 11. Раздел правок

У каждого материала и выпуска может быть вручную заполненный список изменений.

Он располагается в конце страницы:

```text
Правки

5 августа 2026
Исправлена фактическая ошибка в третьем разделе.

12 августа 2026
Обновлена подпись к фотографии.
```

Правки добавляются вручную в метаданные.

Git остаётся полной технической историей, но не показывается читателю.

Не нужно хранить версии материала в отдельной базе данных.

# 12. Галерея

Галерея содержит абсолютно все публичные изображения и видео сайта:

- обложки выпусков;
- обложки материалов;
- изображения внутри статей;
- иллюстрации;
- фотографии;
- видео;
- анимации;
- самостоятельные визуальные работы.

Адрес:

```text
/gallery
```

---

## 12.1. Автоматическое построение галереи

Галерея не заполняется вручную.

Во время сборки специальный скрипт:

1. проходит по всем материалам;
2. извлекает компоненты `<Media>`;
3. читает их метаданные;
4. добавляет обложки;
5. находит все места использования;
6. создаёт общий медиаманифест;
7. проверяет уникальность идентификаторов.

Получается структура:

```ts
{
  id: "city-photo",
  src: "/media/city-photo.webp",
  type: "image",
  alt: "Описание",
  author: "Имя автора",
  source: "Источник",
  license: "CC BY 4.0",
  downloadable: true,
  usages: [
    {
      material: "first-material",
      issue: "issue-001",
      anchor: "media-city-photo",
    },
  ],
}
```

---

## 12.2. Открытие изображения

При нажатии на изображение в галерее открывается модальное окно.

В нём находятся:

- большая версия;
- название;
- описание;
- автор;
- источник;
- лицензия;
- кнопка скачивания;
- список мест использования.

Основное действие:

```text
Открыть в материале
```

Если изображение использовалось несколько раз, пользователь выбирает нужное место.

После перехода сайт:

1. открывает материал или выпуск;
2. прокручивается к изображению;
3. временно выделяет его рамкой или фоном.

---

## 12.3. Скачивание

Для каждого медиафайла доступна кнопка скачивания.

Можно предоставить два варианта:

```text
Скачать оптимизированную версию
Скачать оригинал
```

Если оригиналы слишком тяжёлые, на первой версии можно оставить только один файл.

---

# 13. Метаданные изображений и видео

Метаданные хранятся рядом с использованием файла в материале или в отдельном общем реестре.

Обязательные поля:

- идентификатор;
- файл;
- альтернативное описание;
- автор;
- источник;
- лицензия;
- разрешение на скачивание.

Опциональные поля:

- название;
- дата создания;
- место создания;
- техническое описание;
- подпись;
- ссылка на оригинал.

Один файл может использоваться в нескольких материалах. Его базовые метаданные хранятся один раз, а подпись для конкретного контекста может различаться.

---

# 14. Главная страница

Главная остаётся визуально насыщенной и анимированной.

Она содержит:

- логотип `[N]`;
- последний выпуск;
- крупную обложку;
- название;
- описание;
- кнопку «Читать выпуск»;
- процедурный фон;
- короткий список разделов;
- выбранные материалы;
- несколько медиа из галереи;
- ссылку на архив.

Процедурные композиции:

- основаны на сетке;
- используют банк архетипов;
- меняются каждые четыре секунды;
- не повторяются до исчерпания банка;
- адаптируются под светлую и тёмную тему;
- не перекрывают основную информацию;
- приостанавливаются в неактивной вкладке;
- упрощаются на слабых устройствах.

В режиме чтения эти анимационные модули вообще не загружаются.

---

# 15. Единый стиль

Все выпуски используют одну визуальную систему.

Различаться могут только:

- обложка;
- фотографии;
- иллюстрации;
- содержание;
- порядок блоков;
- композиция медиа.

Не меняются:

- шрифты;
- сетка;
- навигация;
- размеры текста;
- оформление оглавления;
- поведение интерактивных элементов;
- правила анимации;
- структура материала.

Это делает сайт узнаваемым и упрощает разработку новых выпусков.

---

# 16. Что удаляется из первоначального плана

После уточнений больше не нужны:

- PostgreSQL;
- Supabase;
- авторизация;
- `/admin`;
- конструктор выпусков в браузере;
- блочный редактор в браузере;
- статусы материалов;
- статусы выпусков;
- планирование публикации;
- редакционные комментарии;
- совместное редактирование;
- серверная история версий;
- API для сохранения материалов.

Главным интерфейсом редактора становятся:

- VS Code;
- файлы MDX;
- React-компоненты;
- конфигурации TypeScript;
- Git.

```text
├── Создаёт галерею
├── Создаёт страницу людей
├── Создаёт поиск
└── Генерирует карту сайта
```

Главный архитектурный принцип:

> Материал существует как самостоятельный файл, выпуск определяет его редакционный контекст, а весь сайт компилируется из контента во время сборки.
